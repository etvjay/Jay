Reasoned Judgment Protocol

RJP

A judgment layer that turns observable onchain behavior into reproducible evidence, bounded judgments and independently consumed downstream state.

I built RJP to avoid collapsing complex behavior into a global reputation score. Evidence, case construction, assessment, judgment and downstream consumption remain separate artifacts so a consumer can inspect what was observed, why a judgment exists, when it expires and how its own policy should react.

01 / Problem

Raw activity is observable. Actionable trust is an interpretation.

Transactions, approvals and balances do not automatically answer whether a counterparty is safe or a permission target should be trusted.

RJP asks how software can move from observed behavior to a useful judgment without hiding the evidence or pretending one judgment should control every downstream decision.

03 / What I built

The stack spans observation, adjudication and downstream consumption.

Evidence builder

Builds normalized, reproducible Base evidence with observation windows, manifests and Merkle roots.

Protocol objects

DomainSpec, CaseObject, AssessmentArtifact and JudgmentObject schemas and semantics.

GenLayer contract

Stores submitted evidence and revisioned judgments under deterministic or LLM evaluation modes.

Base mirror

Publishes compact judgment state for cheap downstream reads.

Agent benchmarks

Compares judgment-aware and direct agents to test whether the judgment layer changes behavior.

API + frontend

Local adapter and Next.js interface for building cases, submitting judgments and previewing mirrored state.

04 / Technical decision

A judgment should not become downstream policy by accident.

RJP publishes bounded state. The consuming wallet, contract or agent still decides what that state means for its own action.

JudgmentObject
  verdict = SAFE
  domain  = counterparty_trust.base_trade_v1
  subject = 0x…
  window  = [start, end]
  revision = n
  freshness = …

        │
        ▼
consumer policy A → ALLOW
consumer policy B → REVIEW
consumer policy C → ignore domain entirely

This prevents a domain-specific judgment from silently turning into a universal reputation score.

06 / Boundary

RJP does not produce a universal identity score.

A judgment is only meaningful inside its domain, evidence set, observation window, freshness boundary and revision history. Downstream systems retain independent policy and may disagree about what action should follow.

The useful primitive is therefore not “reputation,” but a bounded judgment with enough evidence and context to be independently consumed.
