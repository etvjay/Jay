Noema

Can fragmented representations, claims, and evidence become an economic object software can inspect and reason about without losing the limits of the evidence beneath it?

Foundation implementedEvidence boundary explicitNo live adapter claim
Question Position Model Build Evidence Boundary
01 / Research question

State is not yet understanding.

A balance, event, price, claim, or model output may describe something economically relevant without being enough to justify a stronger economic conclusion.

Noema begins from the narrower problem: how can software carry forward not just a conclusion, but the evidence, verification state, version, freshness, and provenance that constrain what that conclusion is allowed to mean?

02 / Position

Economic understanding should remain reconstructable.

Claims, source evidence, verification state, object versions, roots, and downstream decisions should remain separate enough that a later consumer can inspect how an economic object came to exist.

The useful distinction is not simply raw data versus AI output. It is:

Interpretation boundary
source
  ↓
observation
  ↓
evidence
  ↓
claim
  ↓
verification
  ↓
economic object
  ↓
independent downstream reasoning

The downstream system may still disagree with the interpretation. What should remain inspectable is the path from observation to claim and the evidence ceiling attached to it.

03 / Object model

The economic object carries its own epistemic constraints.

EconomicObject {
  objectVersion
  claims[]
  evidenceRefs[]
  verificationState
  provenance
  freshness
  finality
  lineage
  objectRoot
  evidenceRoot
}

The point is not that every application must use this exact schema. The research question is whether evidence state should remain part of the object’s usable meaning rather than becoming detached metadata.

04 / Build

Freeze the semantic kernel before adding interpretation.

The current Noema repository intentionally focuses on the foundation: shared schemas, semantic cases, deterministic verification, reproducible canonicalization, object roots, evidence roots, and explicit provenance/finality/freshness/version lineage.

That order matters. A live source adapter or model layer added first would make it harder to tell whether later outputs remain reproducible or whether the interpretation silently outran the evidence.

05 / Evidence

The current evidence is foundational, not operational.

What the repository currently supports is narrower than a finished economic intelligence product:

Established

Shared economic kernel, validated schemas, semantic cases, deterministic verification, canonical object/evidence roots, explicit architecture boundary.

Not yet established

Live source ingestion, autonomous AI interpretation, X Layer deployment, MCP server, outbound notification infrastructure.

06 / Claim boundary

Noema should not claim more than the evidence layer can support.

The system is currently best described as an evidence-bounded economic-object foundation, not a complete autonomous intelligence service.

The broader thesis remains open for further experiments: whether financeability, mandates, commitments, watch systems, and agents make better decisions when they consume explicit economic objects instead of free-floating model answers.

Core distinction

State ≠ knowledge. A derived object should not claim stronger evidence than the material that produced it.

Current status

Foundation / schema and verification kernel implemented.
