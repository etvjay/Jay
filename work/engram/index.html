Research question

When can we truthfully claim that an autonomous system learned from a previous execution?

Position

Retrieval is not influence. Prompt inclusion is not causal proof. A prior execution becomes operational memory only when it is recalled under comparable context, explicitly referenced by a later decision, changes action relative to a memory-free control, and leaves enough provenance to reconstruct the relationship.

Experiment

Run controlled scenarios with memory-free baselines, admitted operational lessons, policy-controlled recall, explicit memory influence, counterfactual comparison, and observed later outcomes across routing, deployment recovery, coding regressions, incident recovery, stale memory, and competing-memory cases.

Build

source execution → operational memory → recall → decision → changed action → observed outcome.

Engram implements a versioned execution protocol, runtime, policy system, persistence/vector layers, TypeScript and Python SDKs, HTTP API, semantic MCP, framework adapters, evaluation semantics, and experiment registry.

Evidence

  • Protocol and runtime causal invariants covered by deterministic and conformance tests.
  • SDK, API, MCP, adapter, policy, and evaluation surfaces tested.
  • Multiple execution-memory scenarios preserved as governed experiment records.
  • Claim ledger separates deterministic proof from credential-gated cloud verification.

Current boundary

The external demo workload is simulated. Live CockroachDB Cloud persistence, Bedrock invocation, Managed MCP provenance, natural C-SPANN selection, and AWS deployment remain unverified until credentialed external proof succeeds.

Research lineage
