Engram

Execution-memory infrastructure that tests whether prior experience causally changes later autonomous behavior.

Research questionPositionExperimentBuildEvidenceBoundaryLineageSource

Research question

When can we truthfully claim that an autonomous system learned from a previous execution?

Working position

Retrieval is not influence. Memory becomes operationally meaningful only when a prior execution is recalled under comparable context, explicitly referenced by a later decision, changes the action from a memory-free baseline, and leaves reconstructable provenance.

Experiment

Run controlled execution scenarios with memory-free baselines, admitted operational memory, later recall, explicit influence records, counterfactual comparison, and observed outcomes across multiple domains.

Build

Engram implements an execution-memory protocol and runtime, policy controls, CockroachDB persistence/vector layers, TypeScript and Python SDKs, HTTP API, semantic MCP, framework adapters, control-plane surfaces, and governed experiments.

Evidence

  • Protocol/runtime causal invariants covered by deterministic and conformance tests.
  • SDK, API, MCP, adapter, policy, and evaluation surfaces tested.
  • Multiple stronger execution-memory scenarios preserved under experiments/.
  • Evidence ledger explicitly separates tested behavior from credential-gated cloud claims.

Current boundary

The external demo workload is simulated, and live CockroachDB Cloud, Bedrock, Managed MCP, natural C-SPANN index selection, and AWS deployment are not claimed until credentialed verification proves them.

Research lineage

Execution history → operational memory → policy-governed recall → changed action → observed outcome.
