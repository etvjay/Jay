The Programmable Relationship

What changes when value moves according to the state and authority of a relationship rather than as isolated transactions?

Research synthesisImplemented through multiple primitives
PressureConstructionPropertiesDerived primitivesBoundary
01 / Pressure

A transaction preserves less context than the relationship that produced it.

A transfer can tell us that value moved. It does not, by itself, preserve why the action was permitted, whose authority was exercised, what terms were accepted, what evidence was required, or what should happen when the result diverges from expectation.

transaction
  → consequence

relationship
  → authority
  → commitment
  → evidence
  → execution
  → receipt
  → recovery / continuation
02 / Construction

OpenRails breaks the relationship into explicit state objects.

Workspace  // where the activity exists
   ↓
Path       // what a delegate may repeatedly do
   ↓
Intent     // what is requested now
   ↓
Proposal   // normalized execution candidate
   ↓
Decision   // allowed or blocked by current policy
   ↓
Pact       // what has actually been committed to
   ↓
Proof      // evidence required before a transition
   ↓
Settlement / Receipt
   ↓
Gaia       // exception / rectification if reality diverges

The point is not that every relationship must use these exact names. The experiment is whether preserving these distinctions makes economic activity easier to authorize, inspect, compose and recover.

03 / What the model preserves

Five properties kept reappearing.

Persistence

The context survives individual transactions.

Bounded authority

Actors can participate without receiving unrestricted control.

Commitment lineage

A consequence can be traced back to the terms and policy that admitted it.

Recoverability

Failure can create governed state instead of escaping into an informal support process.

Composition

Multiple relationships can coordinate without losing their individual authority or exposure.

Temporal state

Capacity and permission can change through time rather than existing as a Boolean.

05 / Boundary

This is an application architecture thesis, not a claim that all commerce belongs onchain.

The narrower claim is that a system can preserve more useful economic context when authority, commitments, evidence, execution state and recovery remain explicitly related.

EVM signatures, token standards, account systems and settlement contracts still provide their own lower-level guarantees. The programmable-relationship layer composes those mechanisms into a longer-lived economic state model rather than replacing them.

Core thesis

The relationship can be a more expressive economic state object than the isolated transaction.

Primary systems

  • OpenRails — relationship integrity
  • Concord — relationship composition
  • OTC Chronograph — conditional economic topology

Claim discipline

Different abstraction does not imply universal superiority. Each derived story states where the mechanism is useful and where simpler constructions remain preferable.
