Workspace

A persistent authority context for economic activity that should outlive any single wallet action or transaction.

Question Code Authority binding What it allows Boundary Next primitive
01 / Question

If people, applications, services and agents participate in the same continuing economic activity, where should the shared context live?

wallet → signs an action
workspace → persists the activity, actors, authority and downstream lineage

The Workspace is not the wallet. It can contain several kinds of actors, while membership, role and authority remain explicit protocol state.

03 / Authority binding
The Runtime persists both the Workspace object and the authenticated signer that registered it
private prepareWorkspace(request, binding, state, at) {
  const workspace = request.data.workspace;

  if (state.workspaces[workspace.id] ||
      state.workspaceAuthorities[workspace.id]) {
    throw new RuntimeError("STATE_STALE",
      "Workspace has already been registered.");
  }

  const authority = getAddress(binding.signer);

  return {
    commit: (draft) => {
      draft.workspaces[workspace.id] = clone(workspace);
      draft.workspaceAuthorities[workspace.id] = authority;
    }
  };
}

This produces two related but different facts: who the Workspace says its owner actor is, and which authenticated wallet authority registered the Workspace into the Runtime. The Runtime can later require that stored authority instead of reconstructing it from an arbitrary caller.

04 / What it allows
01Wallet ≠ activity

A cryptographic signer can authorize transitions without becoming the only identity or organizational context the system knows.

02Heterogeneous actors

Humans, agents, applications, services and sidecars can participate inside one persistent context while retaining different roles and authority states.

03Shared provenance root

Paths, Intents, Proposals and Pacts can all reference the same Workspace instead of rediscovering who and what the activity belongs to each time.

04Lifecycle control

A Workspace can be suspended or closed without pretending every downstream object is an unrelated transaction.

Workspace→Actors→Paths→Intents→Pacts→Receipts
05 / Boundary
A Workspace is not a custody container and not a new account abstraction.

It is the persistent coordination and authority context in which later permissions and commitments can be interpreted. Wallets still provide cryptographic authorization; settlement systems remain authoritative for actual value movement.
